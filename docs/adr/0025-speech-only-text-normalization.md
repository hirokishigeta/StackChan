# ADR-0025: 発話テキストのクリーン化は StackChan 側の責務とする

- Status: Accepted
- Date: 2026-06-14
- 関連: ADR-0021 (文単位TTS) / ADR-0024 (HermesAgent) / design-spec §11

## コンテキスト

HermesAgent 経由の応答に URL・マークダウン・コードブロック・ツール出力など「画面で読むための情報」が含まれ、TTS で読み上げると不自然・冗長だった。これらはエージェント（Hermes）側で抑えるのではなく、Hermes はフル情報を自身のメモリに保持しつつ、**StackChan 側が読み上げ用に整形する**べき（処理場所の決定）。

## 決定

発話する `text` を StackChan 側で 2 層でクリーン化する。

1. **プロンプト指示（全エージェント共通）**: 応答フォーマット指示に「`text` は音声で読み上げる。URL/リンク/マークダウン/コード/パス/生のツール出力を入れず、必要なら平易な話し言葉に要約する」を追記（`openai_compatible_gateway` の `_RESPONSE_FORMAT_INSTRUCTION`）。
2. **決定的な後処理（保険）**: `sanitize_for_speech()`（`domain/speech/text_normalization.py`）で URL・マークダウンリンク（ラベルは残す）・コードフェンス・インラインバックティック・見出し/箇条書き/強調記号を除去し空白を整える。`_run_agent_turn` で読み上げ・画面表示の両方に適用。プレーン文は不変、結果が空なら原文にフォールバック。

エージェント側（Hermes）はフル情報をメモリに保持するため、こちらの整形は読み上げ表示のみに影響する。

## 検討した選択肢

- 選択肢 A（採用）: プロンプト指示＋決定的後処理の二層。LLM 非準拠時も確実にクリーン。
- 選択肢 B: プロンプト指示のみ。モデルが従わないと URL が読まれる。
- 選択肢 C: 後処理のみ。プロンプトで自然な要約を促せず、機械的除去で文意が欠けることがある。

## 影響

- 全エージェント（OpenAICompatible / Hermes）で発話がクリーンになる。
- 端末表示も整形後テキスト（URL 等は表示にも出ない＝「読む必要がないものは出さない」方針）。
- フォローアップ: ツール使用の把握と**端末へのツール実行中表示**は、Hermes のストリーミング（SSE `hermes.tool.progress`）受信が必要な別作業として残す。
