# ADR-0027: 発話テキストのクリーン化はプロンプトのみで行う（後処理を廃止）

- Status: Accepted
- Date: 2026-06-14
- 関連: ADR-0025 (これを Supersede) / ADR-0024 (HermesAgent)

## コンテキスト

ADR-0025 では発話クリーン化を「プロンプト指示＋決定的な後処理（`sanitize_for_speech` 正規表現）」の二層にした。しかし後処理が実害を出した：URL 除去の `https?://\S+` が、**空白の無い日本語**ではURL直後の本文まで貪欲に削除し（「…https://x.com今日は晴れ」→「今日は晴れ」が消える）、端末表示で「文が抜ける・誤字に見える」を引き起こした。`\w` も Unicode で日本語にマッチするなど、正規表現での機械的除去は日本語と相性が悪く壊しやすい。

## 決定

発話クリーン化は**プロンプト指示のみ**で行い、**決定的な後処理は廃止**する。

- `OpenAICompatibleGateway._RESPONSE_FORMAT_INSTRUCTION` の「`text` は音声で読み上げる。URL/リンク/マークダウン/コード/パス/生のツール出力を入れず、必要なら平易な話し言葉に要約する」指示を唯一の手段とする（全エージェント共通。Hermes でも送られる）。
- `sanitize_for_speech` とそのテストを削除し、`_run_agent_turn` は `reply.text` をそのまま読み上げ・表示に使う。

## 検討した選択肢

- 選択肢 A（採用）: プロンプトのみ。テキストを壊さない。たまにモデルが URL を含めても文意は保たれる（最悪 URL が読まれる程度）。
- 選択肢 B（ADR-0025）: プロンプト＋正規表現後処理。日本語を破壊するリスクが現実化したため却下。
- 選択肢 C: 言語を意識した高度なサニタイザ（形態素・URL 境界判定）。コスト高でやり過ぎ。

## 影響

- 発話テキストの欠落・誤字化リスクが消える。
- まれにモデルが URL/記号を含めた場合は読み上げに混じりうる（許容。プロンプトで抑制継続）。改善が必要なら正規表現ではなくプロンプト強化で対応する。
- ADR-0025 は Superseded。
