# ADR-0028: ボット自身の発話エコーをバックエンドで除去する

- Status: Accepted
- Date: 2026-06-14
- 関連: ADR-0014 (wake gate) / ADR-0010 (firmware audio) / ADR-0021 (文単位TTS)

## コンテキスト

「初回は良いが2回目以降の会話が崩れる」症状を調査。バックエンドログで、ボット自身の TTS 応答（例「今日はどんなお話をしましょうか?」）が**ユーザー発話として認識され agent に渡っている**ことを確認した。CoreS3 に AEC が無く、デバイスは再生バッファを先読みするため、half-duplex の postroll を過ぎてマイクを開けた時点でもスピーカーから応答の“尻尾”が出ており、それを拾ってしまう。会話がエンゲージ状態だと、このエコーがそのまま次ターンとして処理され、**ボットが自分と会話して劣化**する（初回はエコー元が無いのでクリーン）。

固定 postroll では端末の実再生完了を正確に追えず、デバイス側 AEC は CPU 逼迫（クラックル）と両立しない。

## 決定

**バックエンドでエコーを除去**する（デバイス非依存）。

- セッションに直近のボット応答テキスト `last_reply_text` を保持。
- `_finalize_turn` で ASR 結果を得た直後、ウェイクゲートより前に `is_echo_of(stt, last_reply_text)` を判定し、エコーなら破棄（agent に渡さず、VAD リセットして listening 継続）。
- `is_echo_of`（`domain/speech/echo.py`、純関数）: 正規化後、認識テキスト（5文字以上）が直近応答の部分文字列、または ~80% 以上が連続一致（軽微な誤認識を吸収）ならエコー。短い発話（「うん」等）は誤除去を避けて常に非エコー扱い。

あわせて応答速度・エコー低減のため設定を調整（.env / per-device）: `end_of_turn_silence_ms 2000→1000`、`sherpa_num_threads 2→4`、`downlink_prime_frames 28→14`、`vad_rms_threshold 800→1000`。

## 検討した選択肢

- 選択肢 A（採用）: バックエンドのエコー除去（応答テキスト一致）。デバイス非依存・低リスク・テスト容易。自己会話ループを直接断つ。
- 選択肢 B: デバイス AEC を有効化。本来の解だが CoreS3 では重く、発話中 AFE 停止（クラックル対策 ADR-0023）と相反。
- 選択肢 C: postroll を伸ばす／VAD閾値を上げるだけ。タイミング依存で取りこぼす。閾値調整は併用（補助）。

## 影響

- エンゲージ会話が自分のエコーで劣化しなくなる（2回目以降の改善）。
- まれにユーザーがボットの発話を一語一句復唱すると破棄されうる（許容）。
- テスト: `is_echo_of` 単体＋WSの多ターン統合（エコー破棄・本物の追加発話は通過）を追加。
- フォローアップ: 英語/カタカナ専門用語の ASR 精度（Parakeet の弱点）は別課題。
