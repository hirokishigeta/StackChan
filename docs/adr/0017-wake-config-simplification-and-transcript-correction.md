# ADR-0017: ウェイクワード設定の簡素化と転写補正

- Status: Accepted
- Date: 2026-06-14
- 関連: ADR-0011 / ADR-0014 / docs/design-spec.md §8 / §11.6

## コンテキスト

`WakeWordConfig` には `detection_method`（local/backend）と `max_local_active`
（デバイス側同時有効数）の 2 フィールドがあったが、いずれも実機能に結びついて
いなかった:

- バックエンド側のウェイク検出は `AppSettings.wake_word_gate_enabled`（ADR-0014）
  でゲートしており、`detection_method` を参照していない。
- デバイス側ウェイクは固定のコンパイル済みモデル（esp-sr / WakeNet, ADR-0011）で
  動作し、`max_local_active` による動的な絞り込みは行っていない。

加えて、バックエンド STT がウェイクワードを誤転写することが多い（例: 「ベルちゃん」
→「レルちゃん」/「エルちゃん」）。誤転写バリアントをウェイクワードとして登録して
ゲート一致は維持できるが、誤転写されたままの生テキストが LLM に渡り、AI が崩れた
名前を見てしまう問題があった。

## 決定

1. **設定の簡素化**: `WakeWordConfig` から未使用の `detection_method` /
   `max_local_active` を削除する。ドメイン・シリアライズ・API スキーマ・ダッシュ
   ボードの該当 UI から除去する。`enabled` フラグと `wake_words` リスト
   （id / phrase / enabled / threshold）は維持する。後方互換のため、古い永続化
   行にこれらのキーが残っていてもロード時に無視する（エラーにしない）。
2. **転写補正**: ウェイクゲートが一致したターンでは、エージェントに渡す前に認識
   テキスト中のウェイクフレーズ出現箇所を**正規（canonical）名**（そのデバイスで
   最初に有効なウェイクフレーズ）に置換する。純粋な継続ターン（ウェイクワードを
   含まない engaged-continuation）はそのまま渡す。純粋関数
   `canonicalize_wake_word(text, words, canonical)` を domain に追加する。

## 検討した選択肢

- A: フィールドを残したまま放置 — 設定 UI に意味のない項目が残り、混乱を招く。
- B: フィールドを削除し、ゲート一致時に転写補正を行う（採用）。
- 補正方法として STT 側にバイアスをかける案もあるが、プロバイダ非依存にするため
  ゲート直後のテキスト書き換えで対応する。

## 理由

未使用フィールドの削除は設定面の単純化と誤解の排除になる。転写補正はプロバイダに
依存せず、既存のウェイク一致正規化ロジックを再利用でき、ゲートが無効な場合は完全に
no-op で従来挙動を維持できる。

## 影響

- `WakeWordResponse` から `detection_method` が消える（API レスポンス形状の変更）。
- 古い永続化行・古いクライアントが送る `detection_method` / `max_local_active` は
  ロード/PUT 時に無視され、422 にはならない。
- ゲート有効時、ウェイクワードを含むターンの `stt` 表示とエージェント入力が正規名に
  補正される。ゲート無効時は従来どおり。
