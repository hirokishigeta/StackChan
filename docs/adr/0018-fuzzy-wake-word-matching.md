# ADR-0018: ウェイクワードのファジー（編集距離）一致

- Status: Accepted
- Date: 2026-06-14
- 関連: ADR-0014 / ADR-0017 / docs/design-spec.md §8 / §11.6

## コンテキスト

バックエンドのウェイクゲート（ADR-0014）は sherpa-onnx STT の転写テキストを設定済み
ウェイクワードと `matches_wake_word`（正規化後の部分文字列一致）で照合している。
しかし STT はウェイクワードを大きく誤転写する。例えば「ベルちゃん」が
「ねるちゃん」/「ピルちゃん」/「ピリちゃん」/「べる」/「エル」と聞き取られる。

誤転写バリアントを ADR-0017 のようにすべて列挙して登録するのは非現実的で、
未知の崩れ方には対応できない。少しの編集距離以内のフレーズでも一致させたい。

## 決定

1. ドメインに純粋な Levenshtein（編集距離）ヘルパー `_levenshtein` を追加する
   （外部依存なし。domain は依存を持たない、CLAUDE.md）。
2. `matches_wake_word(text, words, max_dist=0)` を拡張する。既存の完全一致／部分一致／
   正規化一致が成立するか、**または** 正規化テキストの長さ ≈ len(P) の連続ウィンドウが
   正規化フレーズ P と Levenshtein 距離 `tol(P)` 以内なら一致とする。
   - `tol(P)` は長さでスケールし誤検出を抑える: len(P) ≤ 2 で 0、3..4 で 1、≥ 5 で 2。
   - グローバル上限 `STACKCHAN_WAKE_FUZZY_MAX_DIST`（既定 2）で `tol` をキャップする。
     0 でファジーを完全無効化（= 従来の完全一致挙動）。
   - 短いフレーズ（len ≤ 2、例「ベル」「エル」）はファジー対象外（誤発火するため）。
   - しきい値はドメインで設定を読まず、呼び出し側から `max_dist` を渡す。
3. `AppSettings` に `wake_fuzzy_max_dist: int = 2` を追加し、`bot_audio_ws` の
   ゲート判定・エンゲージ判定・補正呼び出しへスレッドする。`matches_wake_word` /
   `canonicalize_wake_word` の `max_dist` は既定 0 なので他の呼び出し側は不変。
4. `canonicalize_wake_word` を拡張し、完全一致が無くファジー一致した場合は最良の
   ファジーウィンドウを正規名に置換する。補正はエンゲージするターンのみ（ADR-0017）。
5. エンドワード一致は完全一致のまま（ファジー化しない。誤終了のリスクが高い）。

## 検討した選択肢

- A: バリアントを列挙し続ける（ADR-0017 のまま）— 未知の崩れに対応できず非現実的。
- B: STT 側にバイアス／ホットワードを掛ける — プロバイダ依存になる。
- C: ゲート直後のテキストに対し編集距離でファジー一致＋補正する（採用）。
  プロバイダ非依存で、既存の正規化ロジックを再利用でき、`max_dist=0` で完全に
  従来挙動へ戻せる。

## 理由

編集距離は崩れの種類（置換・挿入・削除）を一様に扱え、長さスケールの `tol` と
グローバル上限で誤発火を抑えられる。短いフレーズを除外することで「ベル」のような
語が無関係な発話で発火するのを防ぐ。ドメインは設定を読まず呼び出し側が距離を渡す
ため、レイヤー依存ルール（CLAUDE.md）を保つ。

## 影響

- 既定（`wake_fuzzy_max_dist=2`）でゲート有効時、登録フレーズに近い誤転写でも
  エンゲージし、`stt` 表示とエージェント入力が正規名に補正される。
- `wake_fuzzy_max_dist=0` で従来の完全一致挙動に戻る。
- エンドワードの挙動は不変（完全一致）。
- ハードコードしきい値なし（設定 + 長さスケール `tol`）。
