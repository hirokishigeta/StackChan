# ADR-0002: PC バックエンドは既存 server/ (Go) と分離し backend/ に新設する

- Status: Accepted
- Date: 2026-06-12
- 関連: ADR-0001, docs/design-spec.md §4

## コンテキスト

リポジトリには既に `server/`（Go 1.24+ / GoFrame v2 / MySQL）が存在する。これは公式モバイルアプリ向けのクラウドサーバーで、アカウント管理・デバイス紐付け・アプリストア・投稿・XiaoZhi AI 連携（JWT 認証・RSA 暗号化）を担う。新設する PC 側 AI バックエンドをここに同居させるか、別ディレクトリに新設するかを決める必要がある。

## 決定

PC 側 AI バックエンドは `backend/` として新設し、既存 `server/` には手を入れない。

## 検討した選択肢

- A: `server/` (Go) を拡張する
  - メリット: ディレクトリが増えない、既存の認証基盤を流用できる
  - デメリット: 用途が全く異なる（クラウドのアカウント基盤 vs LAN ローカルの AI 処理）。Go は ML エコシステム（Whisper 系 / ONNX / PyTorch / OpenCV）の扱いが Python より不利。既存コードを壊すリスク
- B: `backend/` を Python / FastAPI で新設（採用）
  - メリット: ML / AI ライブラリが豊富、Agent / ASR / Vision モデルを直接ホストできる、既存機能への影響ゼロ、クリーンアーキテクチャを最初から適用できる
  - デメリット: リポジトリ内に Go / Python のサーバーが併存する

## 理由

両者は責務・実行環境・ライフサイクルが完全に異なる（クラウド常設 vs ユーザーのノート PC 上で随時起動）。同居させると依存方向と設定責務が混濁する。ML エコシステムの観点でも Python が適する。

## 影響

- リポジトリのコンポーネントが 5 つになる（firmware / backend / server / app / remote）。CLAUDE.md に役割を明記した
- `server/` は今回の改修対象外とし、原則変更しない。変更が必要になった場合は新しい ADR を起こす
- firmware は接続先として既存クラウド（XiaoZhi）と新 backend のどちらを使うかの切り替えが必要になる可能性がある（Phase 0 調査で既存接続処理を確認して判断し、ADR を残す）
